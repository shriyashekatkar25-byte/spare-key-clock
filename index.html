01 · The decision

One default, two ways to get it wrong

If the default session is too short, every agent user hits a browser login in the middle of their work, and scheduled agents fail at 3 a.m. If it is too long, a token copied off a laptop stays useful to an attacker for days. Admins can override it, but most will never touch the default, so the default is the policy for most customers.

Customer problem

A data engineer wires Claude Code to a workspace on Monday. On Tuesday morning the agent stalls on "re-authenticate in browser." Her nightly agent job failed silently. Meanwhile her security team asks: if that token leaks, how long is it good for?

📌 board: friction vs exposure

Proposed change

Ship one idle-session lifetime (refresh-token TTL) for the default external-agent OAuth apps, with refresh-token rotation so a stolen token dies the moment the real user comes back. Option B: route scheduled agents to machine credentials so humans and robots get different clocks.

📌 board: rollout options

Success metric

Smooth starts: share of agent sessions that begin without a forced login. Target ≥ 90%.

📌 board: north star

Guardrails

Human re-logins per user-week≤ 1.5 Scheduled agent runs broken by expiry≤ 0.5% Mean usable window of a leaked token≤ 24 h Leaked tokens usable > 72 h≤ 5%

04 · The math, from my Monte Carlo course

Composition: build a hard distribution from easy pieces

Nobody's login habits follow a textbook distribution. But a population is a mix of simpler groups, and each group's behavior is a transformation or a sum of simple random draws. Composition methods let me sample the messy whole by sampling the clean parts.

1

Mixture: pick a persona, then sample

To draw a user, first roll which persona they are using the weights, then draw their behavior from that persona only. Scheduled agents are themselves a mixture of daily and weekly jobs.

f(gap) = 0.50·f_chat + 0.35·f_code + 0.15·f_sched
2

Box-Muller: two uniforms, two normals

Turn a pair of uniforms into a radius and an angle, and you get two independent standard normals. Exponentiate a scaled normal and you have a log-normal gap: most gaps short, a few very long.

Z = √(−2 ln U₁) · cos(2π U₂) gap = median · exp(σ·Z)
3

Convolution: add up the gaps

Session times are running sums of gaps, so a user's week is a convolution of many gap draws. Fleet-wide leaks are a sum of rare yes/no events, which is Binomial. Each piece is easy, the sum is what matters.

T_k = gap₁ + … + gap_k leaks ~ Binomial(users, p)
4

Product read-out

A forced login happens when a gap is longer than the lifetime. A leaked token is usable until the earlier of "the lifetime runs out" and "the real user comes back and rotation kills it." Averaging those over draws gives the KPIs.

exposure = min(TTL, next gap)

05 · How I'd run it on real data

From toy personas to fitted ones

Swap my made-up persona parameters for fitted ones: pull real gaps between agent sessions from audit logs, fit a log-normal mixture per client type, then rerun the same simulation. Table names below are illustrative.

-- 1. Gaps between sessions per user and agent client
WITH sessions AS (
  SELECT user_id, client_app, event_time,
         LAG(event_time) OVER (
           PARTITION BY user_id, client_app
           ORDER BY event_time) AS prev_time
  FROM main.agent_auth.token_refresh_events
  WHERE event_date >= current_date() - INTERVAL 28 DAYS
)
SELECT client_app,
       COUNT(*)                                      AS gaps,
       percentile(gap_h, 0.5)                        AS median_gap_h,
       stddev(ln(gap_h))                             AS sigma_log,
       AVG(CASE WHEN gap_h > 24  THEN 1 ELSE 0 END) AS p_over_24h,
       AVG(CASE WHEN gap_h > 168 THEN 1 ELSE 0 END) AS p_over_7d
FROM (SELECT *, (unix_timestamp(event_time)
               - unix_timestamp(prev_time))/3600.0 AS gap_h
      FROM sessions WHERE prev_time IS NOT NULL)
GROUP BY client_app;
# 2. Mixture simulation with fitted parameters
import numpy as np
rng = np.random.default_rng(102)
fit = spark.table("main.agent_auth.gap_fits").toPandas()

def simulate(ttl_h, n=200_000):
    w = fit.share / fit.share.sum()
    k = rng.choice(len(fit), size=n, p=w)       # mixture
    z = rng.standard_normal(n)                  # normals
    gap = fit.median_gap_h.values[k] * np.exp(fit.sigma_log.values[k] * z)
    return {
      "relogin_rate": (gap > ttl_h).mean(),
      "mean_exposure_h": np.minimum(gap, ttl_h).mean(),
      "p_exposed_72h": (np.minimum(gap, ttl_h) > 72).mean(),
    }

for ttl in [1, 8, 24, 72, 168, 720]:
    print(ttl, simulate(ttl))
